# Folio — прокрутка и выделение текста

Патч подготовлен для последнего переданного `folio.zip`. В архиве только изменённые и новые файлы, без зависимостей, шрифтов, `.git`, кэшей и результатов сборки.

## Применение

Распаковать архив в корень проекта рядом с `pubspec.yaml`, с заменой совпадающих файлов. Папки целиком не удалять. Предыдущие изменения текущего проекта (PDF/DOCX на всю ширину и переключение интерфейса PPTX только центральным тапом) сохранены.

Зависимости и их версии не изменены. Требуется пересборка Android-приложения: изменены Kotlin, ресурсы и WebView assets; hot reload недостаточно.

## Изменения

### DOCX/PPTX

- Общая touch-физика в `reader-motion.js`: инерция, сопротивление у границ, возврат пружиной, остановка/подхват анимации пальцем. DOCX прокручивается вертикально; PPTX сохраняет горизонтальную постраничную навигацию.
- Характер отскока приближен к PDF с BouncingScrollPhysics.fast, но это не замена WebView на PDF-движок и не обещание побитово одинакового поведения разных движков.
- Движение документа выполняется одним transform и максимум одной записью scroll-позиции за кадр. Геометрия всех страниц не измеряется на каждом движении пальца.
- Системный Android glow/stretch выключен только у Office WebView, чтобы не наслаивался на нашу пружину.
- При активном выделении или увеличенном visual viewport пользовательские touch-перехватчики уступают управление браузеру. Учтены touchcancel, второй палец, поворот, уход со страницы и reduced motion.
- Свайпы PPTX и тапы по краям по-прежнему не переключают интерфейс.

### Общее меню выделения

DOCX/PPTX теперь показывают тот же Flutter-компонент FolioSelectionToolbar, что PDF/MD/TXT: общая liquid-пилюля с существующими иконками Copy и Select all. Android ActionMode сохраняет нативные маркеры выделения, но не рисует второе системное меню. Локальная тема WebView и drawable-маркеры используют палитру Folio; внешний вид самого документа не перекрашивается.

Во время изменения выделения через мост передаётся только небольшое состояние, без выбранного текста. Геометрия меню измеряется по двум концам диапазона, не по всем символам. На время перетаскивания нативного маркера меню скрывается; появляется после короткого периода без изменений. Повторяющиеся сообщения объединяются. Текст извлекается только при явном Copy и записывается в Android clipboard без передачи в Dart.

Поиск сбрасывает старые DOM-диапазоны до замены текстовых узлов; цвета поисковых отметок Office приведены к палитре приложения.

### PDF

PdfSelectionContextMenu теперь непосредственно наследует Align. Для pdfrx это признак самостоятельно позиционируемого меню. Раньше Align был спрятан внутри StatelessWidget, и pdfrx добавлял второе позиционирование с наблюдением за размером поверх уже позиционируемого FolioSelectionToolbar. Устранён этот потенциальный цикл перерасчёта размеров — вероятный источник зависания при появлении выделения.

Также задана локальная Material selection-тема, добавлены стандартные Material-маркеры вместо стандартных треугольников pdfrx, увеличен ограниченный кэш лупы до 8 МиБ. Повторные асинхронные действия защищены от одновременного запуска, ошибки Copy не сбрасывают выделение. После завершения Copy новое выделение пользователя не очищается.

Сам PDF-движок, прогрессивная загрузка и основная политика рендер-кэша не заменялись. OCR для сканов не добавлялся. Подтвердить исчезновение зависания в проблемном PDF нужно на Android: этот путь не выполнялся в доступной среде.

### MD/TXT

Одна SelectionArea охватывает весь список. В Markdown отключены отдельные SelectableText для каждого блока: Text.rich регистрируется в общей области. У TXT убраны самостоятельные области каждого чанка. Это позволяет расширять выделение за границы абзаца/блока.

Ленивая отрисовка длинных файлов сохранена. Select all отслеживается на уровне документа: Copy получает полный источник TXT или видимый текст Markdown, а не только построенные виджеты. Большой Markdown разбирается в отдельном isolate только по явному Copy; результат кэшируется. Перетаскивание маркера сбрасывает режим полного выделения. Горячая клавиша Copy использует тот же путь.

Длительное нажатие и активное выделение MD/TXT больше не считаются коротким тапом, показывающим интерфейс; прокрутка выделения не переключает кнопки.

## Выполненные проверки

- 83 браузерных теста: все прошли. Это 61 существующий и 22 новых теста. Проверялись реальные bundled HTML/CSS/JS в headless Chromium; swipe/overscroll-тесты используют CDP touch input, а не только синтетические PointerEvent.
- Полный набор выполнялся повторно после финальной правки поведения меню. Последний запуск: 83 tests, OK.
- `node --check` для изменённого office.js и двух новых JS-модулей: без ошибок.
- Два изменённых/новых Kotlin-файла разобраны PSI-парсером установленного Kotlin compiler: синтаксических ошибок нет. Это НЕ компиляция против Android SDK и не проверка нативного ActionMode на устройстве.
- Три новых Android XML-ресурса: корректный XML.
- `tools/check_source_integrity.py`: 119 Dart-файлов, 384 локальных импорта, структурных ошибок нет. Это НЕ Dart analyzer и не проверка типов.
- Добавлены 12 Flutter test/testWidgets-проверок; обновлены прежние тесты Markdown и PDF. Они НЕ запускались: Flutter/Dart SDK в среде отсутствует.

Flutter analyze, Flutter tests, Gradle Android build, APK и запуск на телефоне не выполнялись. Браузерные тесты не проверяют Android ActionMode, Flutter–WebView composition, нативные маркеры, OS clipboard или фактическую производительность PDF. Отдельно проверить старые версии Android System WebView.

## Команды для проекта с установленным SDK

```sh
flutter analyze
flutter test
python -m unittest discover -s tools/office_renderer_tests -p 'test_*.py' -v
flutter build apk --debug
```

Для браузерных тестов нужны Python, Playwright, Chromium и Pillow (как у существующих `test_renderers.py`). Можно указать `CHROMIUM_PATH`.

## Проверка на Android перед релизом

1. В DOCX потянуть начало/конец вверх и вниз; в PPTX — наружу первый/последний слайды. Проверить плавный возврат, быстрый повторный свайп, подхват пружины, поворот во время движения. На увеличенном документе проверить pinch/pan.
2. При видимых и скрытых кнопках PPTX проверить свайп, краевые тапы и центральный тап. Только центральный тап переключает кнопки.
3. В PDF с воспроизводимым зависанием выделить слово, потянуть оба маркера, прокрутить, скопировать, выделить всё. Проверить скорость и отсутствие повторного появления меню/прыжков layout.
4. В MD/TXT выделить несколько абзацев, пройти через границу чанка, затем Select all и Copy большого файла. Сравнить начало и конец вставленного текста. Проверить Ctrl+A/Ctrl+C с клавиатурой.
5. В DOCX/PPTX проверить родные маркеры на Android 13 и более новых версиях, отсутствие системного меню поверх Folio, Copy/Select all, смену ориентации и поиск во время выделения. При ошибке clipboard выделение должно оставаться доступным.
